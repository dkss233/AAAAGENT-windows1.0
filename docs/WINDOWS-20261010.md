# Windows 0.3.0-dev.1 验证范围（2026-10-10）

本文为 Windows 0.3.0-dev.1 源码候选整理当日的分阶段验证结果，不是稳定性承诺或全部验收通过声明。Windows 产品源码位于 `windows/code/`，T3 源码位于 `windows/t3-source/`，与 Mac 入口分开。原始运行日志、私有配置、素材和模型权重不随仓库分发；本页提供可公开的测量摘要，安装步骤见 [Windows 指南](../README-WINDOWS.md)。

同日随后增加的本地 LLM 试验见 [本地对话与框架选择](LOCAL-LLM.md)。下文的语音计时和云端文字审核属于各自独立阶段；本地对话通过 Ollama/OpenAI 兼容适配器单独验证。

## 桌宠与工作台

Windows 外壳使用 Electron 44.4.1 和独立 Node 后端，支持拖动、折叠、展开和控制台入口。角色下拉框可切换视频鲸鱼和 Live2D。视频桌宠相关上游为 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，使用条款和署名见 [第三方说明](../THIRD_PARTY_NOTICES.md)。测试所用本地资源含 106 个 WebM、27 张表情图、162 个可调用 ID；这些资源不随仓库提供。回复表情和工作状态映射到动作，每次只播放一个视频，切换到 Live2D 时释放媒体资源。

实际 Electron 检查覆盖视频播放、透明度、重复切换、Live2D 展示及文字桥接。离线预览回显文字，真实对话和账户功能仍需正式配置；这些界面检查不包含实体麦克风验收。

```powershell
cd windows/code/desktop-pet
npm.cmd ci
npm.cmd run dev
```

工作台使用固定 T3 源码；目标引擎为 Codex 0.160.0、DeepSeek Harness 0.2.0-rc.2、Node 24.13.1、pnpm 11.10.0。Windows 二进制和构建结果需要对应运行清单，不能沿用 Mac 指纹。引擎登录使用自己的账号；任务与个人聊天隔离。新安装需按 [引擎说明](../code/workbench/integration/engine-pins/README.md) 准备资源，不包含本次已登录的本地运行环境。

两种引擎均已通过 T3 HTTP 接口完成实际文件任务：第一轮创建并回读四个数值，第二轮沿用同一原生会话读取结果、写入后续文件。Codex 两轮分别为 18.196 秒、38.334 秒；Harness 为 26.992 秒、15.071 秒。这是完整云端任务耗时，包含模型思考与文件工具执行，不能当作纯转交接口延迟。测试只操作独立的合成任务目录。

修复了 Harness 会话只接受 Unix 绝对路径的问题，以及 Windows 权限核验较慢触发原生 RPC 超时的问题；Windows 请求预算为 15 秒，超时不自动重发任务。应用内窗口与原生桌面客户端的双向状态同步应与上述真实引擎续聊分别验收。

Codex 还经过了交回原生引擎的检查：关闭测试 T3 后，官方 app-server 读到前两轮记录，恢复相同 SID，并在 12.791 秒内完成第三轮文件操作。本次未把 Windows 原生 Codex App 界面的自动刷新作为通过项。

## 本地语音已接入应用

本版通过 OpenAI 兼容回环接口接入现有 ASR/TTS 调用路径。本轮真实推理证据来自应用适配器，不等于微信投递或完整工程语音端到端验收。对话和记忆按各自配置运行；语音测量阶段保留云端对话配置。本地语音服务失败时直接报告错误，不自动调用云端语音。

先安装 [本地语音模块](../local-models/README.md) 所需依赖及对应权重。测试和审核时，每次启动一种模型：

```powershell
cd windows/local-models
node tools/start-speech-phase.mjs sensevoice-small
# 结束该进程后再启动下一个；Ctrl+C 会释放该启动器创建的进程。
node tools/start-speech-phase.mjs gpt-sovits
```

可选 ASR：`sensevoice-small`、`paraformer-zh`、`whisper-small`。可选 TTS：`gpt-sovits`（主方案）、`kokoro-82m`、`qwen3-tts-0.6b`。启动器检查可用内存、GPU 显存、已有语音服务和 Ollama 已加载模型；不自动停止用户的其他程序。启动要求至少 8 GiB 空闲内存，GPU 方案还要求至少 8 GiB 空闲显存；运行期间若低于 4 GiB 内存或 2 GiB 显存，则结束自己创建的模型进程。单模型网关只公开所选模型。

在已完成首次配置的应用中，退出桌宠后保存选择：

```powershell
cd windows/code/desktop-pet
node tools/configure-local-speech.mjs --config ../../.local/model-evaluation/trial/user-trial/config.json --asr sensevoice-small
# 单独审核合成时，用下面的设置替换上面的识别选择：
node tools/configure-local-speech.mjs --config ../../.local/model-evaluation/trial/user-trial/config.json --tts gpt-sovits --voice pet-smoke
```

Kokoro 示例音色为 `3`；Qwen 为 `pet-reference`。`pet-smoke` 是本机 GPT 测试配置中的音色，首次安装需在网关配置中登记自己的参考音频。工具备份原配置、保持原启用状态；`--off` 清除本地语音选择。单独选择 ASR 或 TTS 时，另一项沿用原来的云端设置。也可同时在配置中声明 ASR/TTS，但本次低负载审核应分开启动与测试。

源码升级会使旧运行指纹失效。不要删除 `.local` 数据、密钥或参考音频来解决指纹错误。完成构建和审核后，按 Windows 升级流程重新登记运行文件；离线预览不需要改动个人配置。

配置可选 `outputMode: "text"`，用于只验证云端文字并停止后续语音合成；省略时保留语音输出。该字段接受 `voice` 或 `text`，配置工具会校验后保存。它不启动本地对话模型。

另一次隔离的云端文字后端测试收到 DeepSeek Flash 回复，严格记忆请求也成功返回；问候内容没有需要新增的记忆。发送至回复约 4.14 秒，两次验证的本地账本按登记费率合计记录约 0.059145 元，未核对供应商账单。首次测试的 20 元预留上限不能同时容纳前台 / 后台最坏额度，调整独立测试账本上限后通过，未修改产品预算保护。这项云端文字测试不能覆盖后续本地前台测试出现的后台记忆拒绝。

## 本机延迟与效果

环境：Windows 11 x64、Ryzen 7 9700X、31 GiB 内存、RTX 5070 Ti 16 GiB。语音网关 Node 22.14.0；CPU 推理限制为 2 线程。所有数据来自此次新运行，测量包含应用适配器、HTTP 网关和实际推理，不包含用户说话时间或物理扬声器延迟。

| 模型 | 首次请求 | 后续短句请求 | 结果 |
| --- | --- | --- | --- |
| SenseVoice Small | 1388 ms | 62–97 ms | 9 个合成样音及官方中文录音均返回；官方录音“开放”误识别为“开饭” |
| Paraformer | 1587 ms | 51–75 ms | 同样完成 10 次识别；个别“本地”变成“本店”或“本 d” |
| Whisper-small | 2273 ms | 825–1401 ms | 同样完成 10 次识别；有繁体输出及个别同音词错误，保留中文 UTF-8 修复 |
| GPT-SoVITS v2Pro | 19820 ms | 1302–1576 ms | 3 段 32 kHz WAV，音长 3.94–4.72 秒 |
| Kokoro 82M int8 | 3739 ms | 2435–3140 ms | 3 段 24 kHz WAV，音长 3.36–4.75 秒 |
| Qwen3-TTS 0.6B | 8474 ms | 8630–10773 ms | 3 段 24 kHz WAV，音长 3.04–4.72 秒 |

共 9 段非静音合成音频，27 次交叉转写，另加 3 次官方录音识别。结果全部返回成功；识别错误仍保留在原始 JSON 中。模型加载与首轮预热会额外增加等待，不能把暖请求耗时当作开机即用延迟。

每个 GPU 服务完成后关闭，再启动下一个；ASR 也逐个进程运行。采样最低空闲内存 **7773 MiB**，最高 GPU 总占用 **5849 MiB**（含系统与其他应用）。没有同时启动 ASR、TTS 和本地对话模型。本地验证脚本可生成自己的采样与 WAV，测试音频和原始日志不作为仓库资源分发。

GPT/Qwen 本次使用官方预训练权重和合成参考音频，未验证用户自己的微调音色。这是短中文样例的链路测试，不是噪声、口音、多语言准确率评测，也不是人工音质验收。实际麦克风、扬声器、唤醒和长时间连续使用仍需现场试用。上述语音测量期间未加载本地对话大模型；后续 LLM 阶段另有独立记录。

## 本地 LLM：通过项和未解决项

Ollama 0.40.2 + Qwen3.5 4B Q4_K_M 已经过 OpenAI 兼容接口与真实 `LocalDialogueProvider` 调用。16K 上下文下，Ollama 报告 GPU 分配约 3.38 GiB；适配器四次短调用耗时 0.736–1.159 秒，不含后台记忆和桌面显示。完整设置、冷暖耗时和资源保护见 [本地 LLM](LOCAL-LLM.md)。

这些测试没有全部通过：两次把 `(17 * 23) + 5` 答成 404，正确值是 396；两次上下文复述测试中一次成功，一次改为反问。JSON 结构和表情解析成功不代表事实正确或上下文理解可靠。

完整后端测试中，本地前台返回了回复，没有云端 dialogue 计费记录；后台准入与严格记忆仍调用云服务。前台准入把“不需要长期记忆”判为 none，严格记忆却判为 forget，随后同轮助手的来源扩展被 `source_expansion_contains_future_message` 拒绝。保护未放宽，没有执行计划中的第二轮，该完整链路应记为失败。

严格模型原始响应只保存摘要哈希。只读数据库和诊断用合成计划可复现同样拒绝，但不是原始模型响应的逐字段回放。后续需分别处理意图语义与同轮助手先落库的并发边界；本候选没有实施这部分修复，不能借更换本地模型把已知问题抹去。

9B 只下载和准备，资源检查在加载前拒绝启动，随后用户取消试验。没有 9B 推理、质量、延迟或显存实测值。前台本地不代表严格记忆、摘要、准入、感知或工作台离线。
