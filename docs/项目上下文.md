## 3. 改动 → 必须做的事（决策表）

改了哪个目录，决定你要不要重新构建、要不要重新固定指纹。**这是这个项目最容易忘的一步。**

| 改了什么 | 构建 | 重新固定指纹 |
| --- | --- | --- |
| `desktop/*.mjs`、`desktop/index.html`、`desktop/style.css` | `npm run build:desktop` | 需要 |
| `desktop/electron/**`（主进程、preload） | 不需要（直接加载） | 需要 |
| `management/ui/**` | 不需要 | **不需要**（不在指纹内） |
| `D:\AAAAGENT\windows\tools\**` | 不需要 | **不需要**（不在指纹内） |
| `**.ts`（后端、providers、app） | `npm run build` | 需要 |
| 新增/删除 `desktop/**` 下的文件 | 同上 | 需要，且要 `--activate` |

**重新固定指纹**
```cmd
cd /d D:\AAAAGENT\windows\code\desktop-pet
node tools\repin-config.mjs --check      :: 只看差异
node tools\repin-config.mjs --activate   :: 写入
```

**不做会怎样**：启动时报「试用程序文件缺失或已变化，请使用集成后的同一版本。」
`repin-config` 拒绝改变被固定路径的**集合** —— 若构建新增/删除了 `desktop/**` 下的文件，
它会拒绝，需要走完整首次设置。

**指纹覆盖范围**：`code/desktop-pet/{dist,desktop,tools}`（约 1238 个文件）。
证据：`tools/refresh-runtime.mjs` 的 `for (const name of ['dist','desktop','tools']) await pin(...)`。

**构建命令**
```cmd
npm run check           :: tsc --noEmit，改 .ts 后先跑这个
npm run build           :: tsc + build-wechat + build-wake → dist/
npm run build:desktop   :: build-web + build-presentation-preview → desktop/build/
```
**两个都要跑**（改 .ts 只跑 build 不够，改 desktop 只跑 build:desktop 不够）。

## 5. 语音链路（三段，各有各的坑）

```
麦克风 → ASR 转写 → 对话(DeepSeek) → TTS 合成 → 播放
```

**云端模型名（2026-10-15 实测，百炼端点）**

| 用途 | 可用 | 不可用（不要用） |
| --- | --- | --- |
| ASR | `qwen3-asr-flash` | `qwen3-asr-flash-2026-02-10`（虚构） |
| TTS 主 | `qwen3-tts-flash` | `qwen3-tts-instruct-flash`、`-2026-01-26`（虚构） |
| TTS 情绪 | `qwen-audio-3.0-tts-flash`（音色 longanfengyue/longanlingxi） | — |
| TTS 情绪+ | `qwen-audio-3.0-tts-plus`（音色 longanlingxin） | — |
| 感知 | `qwen3.5-omni-flash-2026-03-15` | — |

**教训**：这个项目里**带日期的模型名多为虚构**。改动模型名之前先实测
（发一次最小请求，看是否 `model_not_found`）。

**模型名改一处不够**：同一个名字被固定在 **3 个地方**，必须一起改，否则启动时报
「这个型号尚未登记适配能力和费用边界」：
1. `providers/<x>.ts` 的常量（运行时实际发送）
2. `app/trial-config.ts` 的校验（启动门）
3. `config.json` 的已登记基线 + `management-settings.json` 的设置

原因：`providers/management-catalog.ts` 用 `config.json` 的型号生成适配器的可选型号列表，
`management/settings.ts` 又要求设置里的型号在该列表内。**改一半必挂。**

`config.json` 有哈希约束（`activation.json.configSha256`）。修改后必须重算，
或跑 `repin-config --activate`。**历史审计校验里的旧型号不要动**（校验的是
`artifacts/` 里的旧记录）。

**MiniMax 语音**：`MiniMax/speech-2.8-turbo`、`-hd` 实测返回
`The product is not activated` —— 是**账号未开通**，不是代码问题。

## 6. 语音唤醒

**模型（5 个文件，精确哈希校验，缺一即整个功能关闭）**

来源：`sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20`（GitHub Releases，走代理下载）

| 目标文件名 | 发布包内文件名 |
| --- | --- |
| `encoder.onnx` | `encoder-epoch-13-avg-2-chunk-8-left-64.int8.onnx` |
| `decoder.onnx` | `decoder-epoch-13-avg-2-chunk-16-left-64.onnx` |
| `joiner.onnx` | `joiner-epoch-13-avg-2-chunk-16-left-64.int8.onnx` |
| `tokens.txt` | `tokens.txt` |
| `silero_vad.onnx` | sherpa-onnx `asr-models` 发布里的同名文件（643,854 字节） |

**原项目的 VAD 哈希（212,860 字节）指向一个公开渠道拿不到的文件**，任何人
都无法启用唤醒。已改为公开可得的版本并实测兼容（`windowSize` 512）。

**一键准备**：`准备唤醒模型.cmd` → 调用 `tools/prepare-wake-models.mjs`
（该脚本从 `media/wake/models.ts` 读校验值，不会与代码脱节）。

**排障用的事实**

- 控制器积压上限 `WAKE_BACKLOG_LIMIT = 64000`（4 秒音频）。
  原为 16000（1 秒），实测这台机器偶发 452 ms 主线程卡顿就撑爆 → 会话 5 秒后自动关闭。
- 检测器本身极快：**隔离下每 32 ms 音频帧往返约 0.1 ms**；
  真实环境实测**平均 9 ms、最慢 452 ms**（渲染器主线程同时画 Live2D）。
- 报错信息是分层透传的 —— 三处曾经把原因吞掉（控制器 catch/onError、
  管理器的固定文案）。**已修**。现在报错会带实测数字，例如
  `检测处理跟不上输入（15872 样本积压，每帧往返 9 ms average, 452 ms slowest over 94 frames）`。
  遇到唤醒问题，**先看这句里的数字**再动手。
- 唤醒只在**本机**监听，未唤醒前不上传音频；退出/重启后需重新开启。

**测试 harness 的坑**：`tests/desktop/ui-harness.mjs` 是自制 DOM 模拟。
它曾缺 `querySelector`/`querySelectorAll`/`closest`/`document.documentElement`/`style.setProperty`，
导致 **22 个测试文件、134 个测试从项目发布起一行断言都跑不到**（渲染器加载即抛错）。
已补齐 → 133 通过。**在 harness 里加 DOM 能力时要保守**：我曾加
`getContext(){return null}` 反而让 4 个通过的测试失败（视频渲染器走了另一条路径），已回退。

**仍失败的 13 个**（都是 harness 建模不足，非产品缺陷）：
`capture-start-order(1)`、`display-controls(2)`、`introduction(1)`、`pet-window-controls(3)`、
`presentation-policy(1)`、`voice-feedback(2)`、`work-feedback(2)`、`work-input(1)`。
它们断言布局几何、焦点顺序、播放调度 —— 需要扩展 harness 才能覆盖。

**别用完整测试套件**（`dist/tests` 全部）做快速验证：跑不完，会超时。按需挑文件跑。

## 11. 我做错过的判断（新会话不要重犯）

1. **基于代码阅读下结论**：把 DSH/descriptor 当成卡死原因，实验自相矛盾仍坚持。

   破坏了有测试保护的语义。**改行为前先看有没有对应测试。**

   其实同一文件 100 行后就已完整接入。
