========================================================================
  AAAAGENT 桌宠 · 使用说明
========================================================================

【零、第一次使用：必须先编译一次】

  从 GitHub 下载下来的是【源码】，不能直接双击运行。

  前提（缺一不可）：

    1. 完整仓库
       请保留整个仓库的目录结构，code\workbench 与 code\desktop-pet 必须
       保持同级。只拷 code\desktop-pet 会编译失败——后端要引用
       ../workbench 下的模块，缺了会报 7 个 TS2307。

    2. Node.js（自带 npm），版本 >= 22.12
       下载：https://nodejs.org/ 选 LTS 版（推荐 22 或 24）
       装完在 cmd 里执行  node -v  能看到版本号即可。

    3. 你自己的 Live2D 模型 和 API Key
       仓库里都不提供：模型在控制台里更换（见第二节），Key 在首次启动时填。

  ------------------------------------------------------------------
  推荐做法：双击  启动桌宠.cmd
  ------------------------------------------------------------------
    第一次（或改动过源码之后）它会先做环境检查：系统、架构、Node 版本、
    是否已有配置、是否有实例在运行。不满足会直接说清原因和解决办法。

    检查通过后自动用国内镜像安装依赖、补齐 Electron 运行时、编译，然后
    启动；第一次启动会打开网页让你填 Key、选模型文件夹。整个过程不需要
    回答 Y/N，也不需要 Python 或 Visual Studio。

    只想检查环境、不改任何文件：
        powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup-windows.ps1 -CheckOnly

    只装依赖并编译、不打开设置页（启动器内部就是这么调的）：
        powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup-windows.ps1 -PrepareOnly

    退出码：0 成功 / 2 环境不满足 / 3 已有配置或实例在运行 / 4 下载或构建失败。

  ------------------------------------------------------------------
  手动做法（在 cmd 里逐条执行）
  ------------------------------------------------------------------
    cd /d "解压出来的路径\code\desktop-pet"
    npm ci
    npm run build
    npm run build:desktop

    三条都成功后，才可以双击  启动桌宠.cmd。

    没编译就双击也不会一头雾水：启动器会自动先做上面的准备；准备不了时
    会直接告诉你缺什么、要装哪个版本。

  ------------------------------------------------------------------
  如果 npm ci 报错（下载超时 / 编译失败）
  ------------------------------------------------------------------

  典型报错：
    · prebuild-install warn install Request timed out
    · gyp ERR! find Python  You need to install the latest version of Python
    · npm error code EPERM

  原因：npm 默认从 GitHub 下载预编译二进制，国内容易超时；超时后会改成
        本地编译，而本地编译需要 Python 和 Visual Studio C++ 生成工具。

  两个办法：
    A. 双击  启动桌宠.cmd ，答 Y（自动走镜像，最省事）
    B. 手动设置镜像后再装：
         cd /d "解压出来的路径\code\desktop-pet"
         set npm_config_registry=https://registry.npmmirror.com
         set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
         set better_sqlite3_binary_host_mirror=https://registry.npmmirror.com/-/binary/better-sqlite3
         npm ci
         npm run build
         npm run build:desktop

  注意：镜像提供的预编译二进制只覆盖 Node 22 / 24 / 25 / 26。
        Node 20 及更早会退回本地编译。请用 Node 22 或 24 的 LTS。

  详细说明见  docs/SETUP.md  和  README-WINDOWS.md。


【一、日常使用】

  启动桌宠：双击  启动桌宠.cmd
  （启动器会打印进度，就绪后自动关闭窗口，桌宠在后台运行。
    后端要预热十几秒，控制台地址才会出现——这期间先别急着打开控制台。）

  退出桌宠：点桌宠面板上的退出按钮，或关闭桌宠窗口。
  （退出时会自动停止桌宠自己启动的 Harness 主机，释放内存）

  控制台（改设置、看状态）：
    用桌宠面板上的「控制台」按钮打开，最稳妥。
    命令行里也会打印一行「控制台: http://127.0.0.1:xxxxx/#token=...」，
    但那行地址【每次启动都会变】（端口随机分配），不要收藏、也不要
    用上一次的旧地址——旧地址必然打不开。

  桌宠右侧的三个圆形按钮（从上到下）：

    🔒  锁定鼠标穿透
        开启后鼠标点击会落到下方窗口；把鼠标移回这个按钮上即可解锁。

    ✥   调整模型
        开启后可用滚轮缩放模型、拖动平移模型。
        长按此按钮可重置模型位置和大小。

    👁  注视鼠标
        开启后模型的眼睛、头部和身体会一起跟随鼠标，
        鼠标移出桌宠窗口后仍然继续跟随。
        再点一次关闭，模型回到静止姿态。

【二、换模型】

  控制台「表情与动作」页 -> 点【更换模型】

  操作：
    1. 在弹出的窗口里选到模型文件夹
       （如果里面还套了一层同名文件夹，程序会自动进入，不用手动点进去）
    2. 看到检查结果后，按提示确认安装
    3. 等它自动完成：安装 → 重建 → 重新固定指纹
    4. 重启桌宠（先退出，再双击 启动桌宠.cmd）

  程序会自动处理这些情况：
    · 模型文件夹外多套一层同名文件夹      → 自动进入
    · 模型缺少表情声明（VTS 导出的常见问题）→ 自动补全
    · 换模型后需要重建渲染器              → 自动重建
    · 换模型后需要重新固定指纹            → 自动完成

  换模型后需要重新设置的部分：
    · 情绪映射和「持续启用」会被清空（因为模型换了，条目对不上了）
    · 需要回控制台的「表情与动作」页重新设置

【三、表情与情绪】

  位置：控制台 →「表情与动作」

  桌宠的表情由「助手这一轮回复的情绪」决定，不是由你输入的情绪决定。
  所以要让桌宠做出某个表情，要说能引出它情绪的话，而不是命令它。

  每张表情卡片上有两个控件：

    ① 对应情绪  —— 下拉框，选这个表情对应哪种情绪
       可选：开心 / 悲伤 / 温柔 / 生气 / 惊讶
       一个情绪只能配一个表情；配到新的表情会自动从旧的那里移过来。

    ② 是否持续启用该表情  —— 勾选框
       勾上后，桌宠会一直保持这个表情的效果。
       典型用途：模型作者署名用的标记类表情 —— 持续启用后该标记就不再显示。
       取消勾选即可恢复。

  卡片上还会显示该表情影响哪些模型参数，便于判断效果是否明显。

  建议：
    · 先随便挑一个配上去，对话试试看有没有变化
    · 外观变化明显的表情适合配「开心」这类常出现的情绪，便于确认效果
    · 署名标记、隐藏部件这类「外观开关」型的表情，适合用「持续启用」
    · 具体有哪些可选，取决于你自己的模型

  注意：表情名来自你自己的模型。本说明不列举具体名称，
  请以控制台里显示的实际条目为准。


========================================================================
【四、什么时候需要"重新固定指纹"】

  指纹 = 一份记录程序文件哈希的清单，启动时校验，保证跑的是验收过的版本。

  需要重新固定：
    · 修改程序代码后
    · 换模型后（换模型工具会自动完成这一步）

  不需要重新固定：
    · 改情绪映射、持续启用等控制台设置（存在别处，立即生效）

  日常使用（换模型、改设置）都不需要手动跑这条命令。
  控制台的【更换模型】会自动完成。

【五、常见问题】

  Q: 双击 .cmd 没反应 / 窗口一闪而过？
  A: 先看窗口里最后几行说了什么，启动器会把缺的东西写清楚。
     · 第一次使用：还没编译 → 见第零节
     · 提示找不到 node → 没装 Node.js 或没加进 PATH
     · 早期版本还有过 LF 换行导致 cmd 解析失败，已修复为 CRLF

  Q: 双击后安装/编译都过了，但一直没有桌宠窗口？
  A: 再双击一次  启动桌宠.cmd 。安装器会自动补下 Electron 运行时
     （约 100 MB，第一次安装时容易漏），补完就会正常出现。
     仍然不行就看  .local\pet-launch.err.log  的最后几行。

  Q: 控制台打不开？
  A: 用面板上的「控制台」按钮，它读的是当前实例的真实地址。
     旧标签页/收藏夹里的地址是上一个实例的端口，必然打不开。
     另外后端刚启动要预热十几秒，这期间打不开是正常的。

  Q: 启动时提示「试用程序文件缺失或已变化」？
  A: 程序文件被改动过但没重新固定。在
       <项目根>\code\desktop-pet
     目录里执行：
       node tools\repin-config.mjs --activate
     然后重启桌宠。
     （<项目根> 就是你放这个项目的位置，例如 D:\AAAAGENT\windows）

  Q: 换了模型后控制台报「只能隐藏本模型的预设条目」？
  A: 旧设置里残留了上一个模型的条目。已修复为启动时自动丢弃失效设置。
     如果仍出现，重启一次桌宠即可。

  Q: 情绪映射配好了，但桌宠表情没变化？
  A: 检查四件事：
     1. 该情绪对应的表情是否在「允许自动使用」范围内
     2. 对话时助手是否真的用了那个情绪（说能引出情绪的话）
     3. 该表情在你模型上的变化是否足够明显
     4. 换一个外观差异更大的表情试试

  Q: 后台有个 cmd 窗口？
  A: 正常情况下不应该有。启动器已改为直接运行 node，不创建控制台窗口。
     如果看到 cmd 窗口，请把它的标题告诉协助者。

  Q: 控制台里 Harness 显示「不可用」？
  A: 正常。主机默认不启动，只在你让它执行 DSH 任务时才需要，见第七节。

  Q: 控制台里 Harness 显示「未安装」？
  A: 这台机器还没装 DSH 引擎。点同一个按钮（此时写着「安装 DSH 引擎」），
     会从镜像下载并装配约 1 GB 的运行时，只需一次；装完按钮变回
     「启动 Harness」。安装日志在  .local\engine-prepare.log 。

  Q: Harness 回执显示「暂时无法核实这次任务的状态；不会自动重试」？
  A: 两种原因——
     · 主机是冷的：确认任务时要先启动主机，首次约等 10~45 秒，耐心等它跑完。
     · 旧版本留下的坏回执：那条任务的会话当时根本没建起来，救不回来。
       重新整理一次任务卡再发送即可。

  Q: 控制台「记忆与对话」里的当前情绪显示「暂无」？
  A: 情绪按回合产生。先进行一轮对话再看；如果一直为空，把控制台
     「记忆与对话」页的截图和  .local\memory-lifecycle.log  一起给协助者。

  Q: 点了「在 Harness 中查看」，浏览器报 dsh web authentication required？
  A: 说明打开的地址没带上这次主机的认证。正常流程会先打开一个认证标签页，
     再打开落在具体会话的标签页；若只有报错页，通常是用了旧地址——
     回控制台重新点一次按钮即可。

【六、语音唤醒（可选）】

  什么是语音唤醒：不用点按钮，直接喊唤醒词就能开始对话。
  默认关闭；开启后只在本机持续监听，未唤醒前不会上传任何音频。

  开启步骤：
    1. 控制台「模型与声音」页 ->「语音唤醒」-> 点【安装唤醒模型】
       （会从镜像下载约 33 MB 的模型并校验，只需做一次）
    2. 重启桌宠
    3. 回到这一页，设置唤醒词并点开启

  说明：
    · 唤醒词必须是 2-12 个汉字，默认「德克萨斯」
    · 灵敏度可选 更灵敏 / 标准 / 更严格
    · 每次回复后自动回到等待唤醒状态
    · 退出或重启桌宠后需要重新开启（不会自动恢复）
    · 按住语音键仍可直接说话，不受影响

  如果不准备模型，该功能会显示「本地唤醒模块尚未就绪」且无法开启，
  其余功能不受影响。

【七、Harness 主机（按需启动）】

  桌宠的对话、语音、表情都不需要 Harness 主机，所以它默认【不启动】。
  Harness 主机约占 400+ MB 内存，只有让桌宠执行 DSH 任务时才需要。

  两种启动方式（任选其一）：

    1. 控制台 →「任务转发」页 → 点【启动 Harness】按钮
       （冷启动约 10~45 秒，状态会自动刷新；按钮显示「已就绪」才算好）

    2. 直接下达 DSH 任务（例如"使用 harness 查看工作区目录"）
       主机会在确认执行时自动启动，确认那一步会多等一会儿

  查看状态：控制台「任务转发」页会显示 Harness 是否就绪。
  显示「不可用」是正常的 —— 表示主机还没启动，不是故障。
  显示「未安装」则是引擎还没装，见第五节最后几条。

  退出桌宠时：
    · 桌宠会【自动停止它自己启动的】Harness 主机，释放约 400+ MB 内存
    · 从控制台【启动 Harness】按钮启动的主机不会被动 —— 那属于你的手动操作
    · 想让主机一直留着（方便反复使用），设置环境变量
        AAAAGENT_KEEP_HARNESS=1
      再启动桌宠即可
